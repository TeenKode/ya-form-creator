# Правила создания JSON для YaFormCreator (для ИИ)

**Задача ИИ:** по документу или описанию создать **один UTF-8 JSON-файл** для импорта в YaFormCreator. Не добавлять Markdown, комментарии или пояснения внутрь JSON. Никаких готовых анкет в репозитории нет.

1. **Корень** — объект с обязательными полями `form` и `questions`; опционально `conditions`.
2. **`form`** — объект: `name` (непустая строка, обязательно); `allow_multiple_answers`, `need_auth`, `publish_by_default` (булевы, по умолчанию `true`, `false`, `false` соответственно); по желанию `submit_text`, `success_title`, `success_subtitle` (строки). Не включать креды и персональные данные.
3. **`questions`** — непустой массив объектов в порядке отображения. Каждый объект обязан иметь `type` и `label` (непустой текст). Для всех типов, кроме `section`/`comment`, обязателен **уникальный** `slug` по шаблону `[A-Za-z][A-Za-z0-9_-]*`. `required` — булево (по умолчанию `false`); `comment` — пояснение к вопросу.
4. **Типы:** `radio` — один ответ; `checkbox` — несколько; `dropdown` — список; `scale`, `stars`, `onerow` — шкалы; `text` — текст (`multiline`: `true/false`); `integer` — целое; `date` — дата; `boolean` — да/нет; `matrix` — таблица; `section` — заголовок раздела; `comment` — информационный блок; `api` — расширенный API-объект (`payload`). Тип `api` использовать только при точном знании схемы API.
5. **Варианты:** для `radio`, `checkbox`, `dropdown`, `scale`, `stars`, `onerow` поле `options` обязательно: массив не менее чем из **двух уникальных** строк или объектов с полем `label`. Для тестов допускаются объекты вариантов с `correct: true/false`, `scores: число` и флаг `has_quiz: true` у вопроса (если это предусмотрено исходным заданием).
6. **Ограничения:** `checkbox` — `min_choices`/`max_choices` (целые ≥ 0, не больше количества обычных вариантов); `text` — `min_length`/`max_length` (целые ≥ 0); `integer` — `min`/`max` (целые); `date` — `min`/`max` в `YYYY-MM-DD`. Минимум не может превышать максимум.
7. **Взаимоисключающие ответы (`checkbox`):** добавляйте `exclusive_options` — массив точных подписей вариантов, которые нельзя сочетать с другими (например, отрицательный ответ, «Ничего из перечисленного», «Затрудняюсь ответить»). Эти подписи должны входить в `options`; после исключения должны оставаться минимум два обычных варианта. Если поле не задано, программа автоматически узнаёт распространённые отрицательные ответы. Программа превращает такой вопрос в переключатель с одним ответом и условный список галочек, чтобы запрет работал **в Яндекс Формах**, а не только в предпросмотре. `exclusive_options: []` явно отключает автоматическое распознавание. Если вопрос зависит от предыдущих ответов, настройте `conditions` отдельно; не смешивайте обычные и исключающие ответы одного источника в одном условии.\n8. **Таблица:** у `matrix` обязательны `rows` (не менее 1) и `columns` (не менее 2) — списки уникальных строк или объектов с `label`.
9. **Вариант «Другое»:** у `radio`/`checkbox`/`dropdown` добавьте `other: {"option":"Другое","label":"Уточните ответ"}` **только если** строка `"Другое"` присутствует в `options`. Программа сама создаёт и показывает отдельное текстовое поле. Можно указать уникальный `other.slug`.
10. **Условия показа:** `conditions` — список объектов с `target` (slug зависимого вопроса), `source` (slug предыдущего `radio`/`checkbox`/`dropdown`), `answers` (непустой массив точных подписей вариантов источника). Опционально `operator: "and" | "or"`, `condition: "eq" | "neq"`. Не создавать циклы и ссылки на несуществующие вопросы. При зависимых вопросах о применении ИИ, навыках и инструментах учитывайте ответ «Не использую» в предыдущем вопросе: скрывайте неприменимые вопросы или делайте отдельный ответ «Не использую». Взаимоисключение внутри одного checkbox автоматически НЕ заменяет межвопросные условия. Для `other` отдельное условие не требуется.
11. **Проверка:** не менять смысл и порядок исходных вопросов; не придумывать пропущенные варианты или правильные ответы; сохранять русский текст и специальную пунктуацию. Проверить валидность JSON, уникальность `slug`, соответствие типов, вариантов, зависимостей и ограничения; затем использовать **«Проверить»** в программе либо `python create_yandex_form.py --config FILE.json --validate`. Создание формы доступно только после проверки.

**Инструкция для копирования в другой ИИ:** «Преобразуй приложенную анкету или её описание в один JSON-файл YaFormCreator строго по `AI_JSON_RULES.md`. Сохрани все вопросы и варианты в исходном порядке, правильно выбери типы и обязательность, не выдумывай отсутствующие сведения. Ответ — только содержимое валидного JSON в UTF-8, без комментариев и Markdown».
