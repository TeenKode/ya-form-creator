# Правила создания JSON для YaFormCreator (для ИИ)

**Входная точка:** сначала прочитайте [AGENTS.md](AGENTS.md) и [START_HERE_AI.md](START_HERE_AI.md). Выбор специальных полей описан в [FIELD_GUIDE_RU.md](docs/FIELD_GUIDE_RU.md). Машиночитаемая схема: [schema/form.schema.json](schema/form.schema.json). Поддержка `text.format` требует приложения **1.1.0+**.

**Задача ИИ:** по документу или описанию создать **один UTF-8 JSON-файл** для импорта в YaFormCreator. Не добавлять Markdown, комментарии или пояснения внутрь JSON. Никаких готовых анкет в репозитории нет.

1. **Корень** — объект с обязательными полями `form` и `questions`; опционально `conditions`.
2. **`form`** — объект: `name` (непустая строка, обязательно); `allow_multiple_answers`, `need_auth`, `publish_by_default` (булевы, по умолчанию `true`, `false`, `false` соответственно); по желанию `submit_text`, `success_title`, `success_subtitle` (строки). Не включать креды и персональные данные.
3. **`questions`** — непустой массив объектов в порядке отображения. Каждый объект обязан иметь `type` и `label` (непустой текст). Для всех типов, кроме `section`/`comment`, обязателен **уникальный** `slug` по шаблону `[A-Za-z][A-Za-z0-9_-]*`. `required` — булево (по умолчанию `false`); `comment` — пояснение к вопросу.
4. **Типы:** `radio` — один ответ; `checkbox` — несколько; `dropdown` — список; `scale`, `stars`, `onerow` — шкалы; `text` — текст (`multiline`: `true/false`); `integer` — целое; `date` — дата; `boolean` — да/нет; `matrix` — таблица; `section` — заголовок раздела; `comment` — информационный блок; `api` — расширенный API-объект (`payload`). Тип `api` использовать только при точном знании схемы API.
5. **Варианты:** для `radio`, `checkbox`, `dropdown`, `scale`, `stars`, `onerow` поле `options` обязательно: массив не менее чем из **двух уникальных** строк или объектов с полем `label`. Для тестов допускаются объекты вариантов с `correct: true/false`, `scores: число` и флаг `has_quiz: true` у вопроса (если это предусмотрено исходным заданием).
6. **Ограничения:** `checkbox` — `min_choices`/`max_choices` (целые ≥ 0, не больше количества вариантов); `text` — `min_length`/`max_length` (целые ≥ 0); `integer` — `min`/`max` (целые); `date` — `min`/`max` в `YYYY-MM-DD`. Минимум не может превышать максимум.
7. **Таблица:** у `matrix` обязательны `rows` (не менее 1) и `columns` (не менее 2) — списки уникальных строк или объектов с `label`.
8. **Вариант «Другое»:** у `radio`/`checkbox`/`dropdown` добавьте `other: {"option":"Другое","label":"Уточните ответ"}` **только если** строка `"Другое"` присутствует в `options`. Программа сама создаёт и показывает отдельное текстовое поле. Можно указать уникальный `other.slug`.
9. **Условия показа:** `conditions` — список объектов с `target` (slug зависимого вопроса), `source` (slug предыдущего `radio`/`checkbox`/`dropdown`), `answers` (непустой массив точных подписей вариантов источника). Опционально `operator: "and" | "or"`, `condition: "eq" | "neq"`. Не создавать циклы и ссылки на несуществующие вопросы. Для `other` отдельное условие не требуется.
10. **Проверка:** не менять смысл и порядок исходных вопросов; не придумывать пропущенные варианты или правильные ответы; сохранять русский текст и специальную пунктуацию. Проверить валидность JSON, уникальность `slug`, соответствие типов, вариантов, зависимостей и ограничения; затем использовать **«Проверить»** в программе либо `python create_yandex_form.py --config FILE.json --validate`. Создание формы доступно только после проверки.

11. **Специальный текст:** `type: "text"`, `format: "plain" | "full_name" | "phone" | "email" | "url" | "inn" | "decimal"`. Для всех форматов, кроме plain, задайте `multiline: false`. В API это `string` с нужным валидатором; full_name — обычная строка без проверки имени. Не выдумывать типы fio/phone/email/number/string в конфигурации.
12. **Номер — не обязательно число:** телефон, ИНН, номер документа/заказа/договора, индекс и банковские идентификаторы хранить строкой (`text`), чтобы не терять ведущие нули и знаки. `integer` предназначен для целочисленного значения (например количества); дробное значение — `text` с format decimal. Если «номер» не уточнён, сначала спросить назначение. Телефон phone — для РФ; международный телефон — однострочный plain-текст с согласованными требованиями.
13. **Ограничения должны работать:** не добавлять `unique`, `validation`, `validators`, `pattern` и `regex` прямо в вопрос: они не входят в этот формат и вызывают ошибку. Штатные проверки выбираются через format. Проверка неповторяемости ответа среди участников не реализована; не обещать её через уникальный slug или запрет повторного заполнения. Для нестандартного API валидаторы задаются только внутри api.payload по подтверждённой документации.
14. **Не заполнять форму:** не добавлять токены, org_id, ClientID или реальные ответы в конфигурацию; не подставлять ФИО, телефон, почту и документы через initial/default. Сохранять обязательность из задания, не придумывать обязательное отчество, длины и маски. `publish_by_default` всегда false при подготовке ИИ, если пользователь отдельно не попросил иной режим.
15. **Offline-проверка результата:** `python check_agent_form.py --config FILE.json`, затем `python create_yandex_form.py --config FILE.json --dry-run`. Устранить ошибки и разобраться с предупреждениями. Если выполнить команды невозможно, не писать, что тесты прошли. Не отправлять запросы к API без отдельного запроса пользователя.

**Инструкция для копирования в другой ИИ:** «Преобразуй приложенную анкету или её описание в один JSON-файл YaFormCreator строго по `AI_JSON_RULES.md`. Сохрани все вопросы и варианты в исходном порядке, правильно выбери типы и обязательность, не выдумывай отсутствующие сведения. Ответ — только содержимое валидного JSON в UTF-8, без комментариев и Markdown».
