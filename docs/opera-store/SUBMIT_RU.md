# Публикация в Opera Add-ons

Версия 1.6.1 отправлена на модерацию Opera; это ещё не одобрение и не публичная публикация.

Пакет содержит ZIP расширения, иконку, описание и заметки проверяющему. ZIP загружается как расширение; папку listing и скриншоты отдельно в ZIP расширения включать не нужно.

1. Войдите или зарегистрируйтесь на https://addons.opera.com/developer/. Регистрацию, подтверждение почты, CAPTCHA и принятие соглашений выполните самостоятельно.
2. Загрузите yaform-opera-VERSION.zip. Магазин назначает ID: не считайте его равным ID распакованной сборки. Для первой магазинной записи назначен ID bjcopighflhaahbconmpgodlnkbifklk.
3. Проверьте адрес возврата в настройках магазинной сборки. Добавьте его в разрешённые Redirect URI общего приложения Яндекс OAuth a7f96f176b4241449864e48e3c3c6966, сохранив прежний адрес для ZIP-сборки. Не публикуйте Client secret или токен.
4. До отправки на модерацию проверьте реальный вход через Яндекс, подключение организации и создание тестового черновика в Opera. Отдельно проверьте магазинную сборку в Яндекс Браузере. CI с подменённым API не заменяет эту проверку.
5. Заполните карточку из LISTING_RU.txt. Категория Productivity. Загрузите icon64.png (64×64) и снимки screenshots/store-*.png (800×600; демонстрационные данные). Не обещайте совместимость, которую не проверили.
6. Политика: https://teenkode.github.io/ya-form-creator/privacy.html. Проверьте, что страница опубликована и описание обработки соответствует текущему коду.
7. Выберите условия лицензирования осознанно. В репозитории нет общей LICENSE; публичный GitHub не означает разрешения на любое использование. В инструкции Opera указано, что при отсутствии отдельной EULA применяется CC BY-NC-ND 4.0 для конечных пользователей. Эта подготовка не добавляет лицензию и не меняет права на репозиторий. Если нужны другие условия, владелец должен утвердить их перед отправкой.
8. Вставьте REVIEWER_NOTES_EN.txt в заметки модератору, обновив результаты живой проверки и фактический ID. Учётные данные личного аккаунта передавать нельзя; если магазин попросит тестовый доступ, используйте отдельный аккаунт без личных данных.
9. Просмотрите итоговую карточку и подтвердите отправку. Модерация ручная, срок и одобрение не гарантированы. До одобрения ссылка магазина на сайте не заменяет существующий ZIP.

## Воспроизвести пакет

```sh
npm ci
python scripts/build_browser.py
node scripts/build_opera.mjs
```

Результат: browser-build/opera-submission/. Скриншоты создаются только браузерным CI; локальная команда при их отсутствии это явно сообщает. Исходники пакета форматируются Prettier без обфускации. Публичный development key удаляется только из магазинного пакета; исходный ZIP сохраняет прежний ID. Остальные файлы не меняют поведения приложения.

CI отдельно проверяет расширение в Chromium и официальной закреплённой сборке Opera. Пакет Opera скачивается с deb.opera.com и проверяется по SHA-256; смена версии/хеша требует явного изменения scripts/prepare_opera_ci.py. OAuth и Forms API в тестах синтетические. Для обновлений увеличивайте manifest version, сохраняйте запись магазина и проверяйте OAuth Redirect URI.
