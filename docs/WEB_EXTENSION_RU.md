# Сайт и расширение YaFormCreator

**[Открыть веб-приложение](https://teenkode.github.io/ya-form-creator/)**. Оно размещается на GitHub Pages и работает без сервера приложения. Каждый пользователь подключает свой аккаунт и организацию; получает собственный токен. Аккаунт владельца репозитория не используется для создания чужих форм.

## Установка расширения

1. На сайте нажмите «Подключить расширение» → «Скачать расширение». [Прямая ссылка на ZIP](https://teenkode.github.io/ya-form-creator/yaform-extension.zip).
2. Распакуйте архив в постоянную папку. Не удаляйте её после установки.
3. Откройте управление расширениями: `chrome://extensions`, `edge://extensions` или страницу расширений Яндекс Браузера.
4. Включите **режим разработчика**, нажмите **«Загрузить распакованное»**, выберите папку с `manifest.json`.
5. Для этой распакованной сборки ожидаемый ID: `ojjljnbbienealjljlfklnfdpfemmlli`. Его закрепляет публичный ключ в manifest; это не секрет и не ключ доступа к Яндексу.
6. Обновите сайт. Должна появиться надпись «Расширение подключено».

Расширение пока не опубликовано в магазинах. Основная платформа — актуальный Chrome на компьютере. Edge и Яндекс Браузер поддерживают расширения Chromium, но OAuth следует проверять в конкретной версии браузера. Firefox и мобильные браузеры в эту сборку не входят. Для обновления замените файлы в папке, нажмите «Обновить» в управлении расширениями и перезагрузите сайт.

## Организация и вход

API рассчитан на **Формы для бизнеса**. OAuth не создаёт организацию, не оформляет подписку и не выдаёт права администратора. Создание Яндекс 360 / Cloud, получение ID и токенов подробно описаны в [SETUP_RU.md](SETUP_RU.md).

1. Нажмите на сайте «Настроить подключение». Откроется отдельная страница расширения.
2. Выберите **Яндекс 360** (`X-Org-Id`) или **Yandex Cloud / Identity Hub** (`X-Cloud-Org-Id`).
3. Нажмите **«Войти через Яндекс»**. ClientID сервиса уже заполнен. Войдите в свой аккаунт и разрешите доступ к Формам и чтение списка организаций Яндекс 360. Вход больше не требует ID организации.
4. Выберите организацию по названию. Если найдена одна и ещё ничего не выбрано, расширение проверит доступ к Фoрмам и сохранит выбор автоматически. Если список недоступен, раскройте «Указать ID вручную». Для поиска организаций Cloud используйте пользовательский IAM-токен.
5. Нажмите «Проверить доступ». Если для федеративного аккаунта OAuth недоступен, используйте IAM-токен и тип Yandex Cloud.

Ручной вход: раскройте «Или вставить готовый токен», выберите OAuth / IAM, вставьте токен **без префикса** `OAuth` / `Bearer` и сохраните подключение. IAM работает только с `X-Cloud-Org-Id`. Получение токена: [инструкция](SETUP_RU.md).

По умолчанию токен хранится в `chrome.storage.session` до завершения сеанса браузера. Флажок **«Запомнить токен после закрытия браузера»** дополнительно сохраняет его в `chrome.storage.local`, без шифрования и без синхронизации. На общем компьютере не включайте запоминание. Если Яндекс вернул срок действия токена, расширение проверяет его; автоматического продления нет. После истечения срока войдите заново.

«Выйти» удаляет обе локальные копии токена и список найденных организаций. Для отзыва самого доступа удалите разрешение приложения в настройках безопасности Яндекс ID.

### Автоматический поиск организаций

Яндекс 360: используется `GET https://api360.yandex.net/directory/v1/org` с разрешением `directory:read_organization`. Владелец OAuth-приложения добавляет это разрешение один раз; пользователи входят заново, отдельное приложение каждому не нужно. Доступ к списку зависит от прав и роли пользователя. Если Яндекс вернул отказ, остаётся ручной ввод ID.

Cloud / Identity Hub: используется `GET https://organization-manager.api.cloud.yandex.net/organization-manager/v1/organizations` с пользовательским IAM-токеном. Новые OAuth-токены Яндекс ID больше не принимаются для обмена на IAM в Yandex Cloud с 1 июня 2026 года, поэтому расширение не выполняет такой обмен и не запрашивает `cloud_api`. При входе в Формы через OAuth ID Cloud можно указать вручную.

Расширение читает только список названий и ID, обрабатывает страницы ответа и проверяет доступ к Формам перед сохранением выбранного варианта. Никакая организация не создаётся. Контакты из справочника не сохраняются; список привязан к текущему токену и обновляется после смены аккаунта. Выбор из старого списка истекает через 10 минут. Наличие организации в списке не доказывает доступ к Фoрмам.

Источники: [список организаций 360](https://yandex.ru/dev/api360/doc/ru/ref/OrganizationsService/OrganizationsService_List), [список Cloud](https://yandex.cloud/ru/docs/organization/api-ref/Organization/list), [изменения OAuth Cloud](https://yandex.cloud/ru/docs/iam/concepts/authorization/oauth-token).

## Мастер создания организации Identity Hub

В настройках расширения нажмите **«Создать организацию Cloud»**. Мастер откроет [Cloud Center](https://center.yandex.cloud/). Создайте организацию там и подтвердите условия сами, затем вернитесь в расширение. Проверьте, что новая организация доступна в Формах для бизнеса, подключите пользовательский IAM-токен и нажмите **«Я создал организацию — найти её»**.

Если расширение уже читало список Cloud-организаций с этим токеном, оно сравнит ID до и после перехода. При одном новом варианте проверит доступ к Формам и сохранит его; иначе предложит выбор. При отсутствии исходного списка или смене токена показывается текущий список без утверждения, что эти организации созданы только что. Если организация одна и ещё ничего не выбрано, она проверяется и выбирается автоматически. Закрытие мастера не удаляет организацию.

Это **помощник с ручным подтверждением**, а не автоматическое создание через API: в публичном [Organization API](https://yandex.cloud/ru/docs/organization/api-ref/Organization/) нет метода Create. Поддерживаемый путь — [создание в Cloud Center](https://yandex.cloud/ru/docs/organization/quickstart). Расширение не использует внутренние методы консоли и не принимает соглашения за пользователя. Создание облаков, платёжных аккаунтов, подписок и платных ресурсов в мастер не входит. Условия стоимости подключённых сервисов проверяйте отдельно: [тарификация Identity Hub](https://yandex.cloud/ru/docs/organization/pricing).

Мастер хранит только исходные ID и привязку к текущему токену в сеансе расширения; срок шага — 24 часа. Поиск выполняется по явному нажатию, без фонового опроса. Вход через общий OAuth и поиск организаций Яндекс 360 остаются доступны отдельно.

## Создание анкеты

Если ИИ не открывает GitHub, нажмите на сайте «Создать с ИИ»: скопируйте готовые правила или скачайте один TXT и передайте его в чат вместе со своим заданием. Доступ к репозиторию не нужен. [Подробнее](AI_OFFLINE_RU.md).

1. Откройте UTF-8 JSON (до 750 000 байт) либо добавьте вопросы вручную. Для ИИ используйте [START_HERE_AI.md](../START_HERE_AI.md).
2. Проверьте название, вопросы и условия справа. Расширенные настройки доступны в «Редактировать JSON»; применяйте их кнопкой. Предпросмотр имитирует поведение и не заменяет проверку готовой формы в Яндексе.
3. Сохраните JSON на компьютер. Рабочая копия сохраняется также в localStorage сайта; очистка данных браузера удалит её. Ответы предпросмотра остаются только в памяти.
4. Нажмите **«Создать в Яндексе»**. Откроется вкладка расширения с названием, полным JSON, числом вопросов и организацией.
5. Проверьте данные, отметьте подтверждение и нажмите **«Создать черновик»**. Публикация выключена по умолчанию независимо от `publish_by_default` в файле. Для неё нужно отдельно поставить флажок в расширении.
6. Откройте редактирование созданной формы в Яндексе и проверьте результат.

Каждый запуск создаёт **новую** форму. Обновление существующих анкет и сбор ответов не поддерживаются. Не закрывайте браузер во время отправки.

### Специальные поля

Сохраняется контракт настольной версии 1.2+: `text` с `format: full_name / phone / email / url / inn / decimal`. ФИО не требует обязательного отчества; телефон РФ использует нативный валидатор Яндекса. Номер документа с ведущими нулями — обычный текст, счётчик — `integer`, дробное число — `text + decimal`. Уникальный `slug` означает код вопроса, а не запрет повторных ответов. [Справочник полей](FIELD_GUIDE_RU.md).

## Ошибки и ограничения

| Ситуация | Что делать |
| --- | --- |
| Сайт не видит расширение | Проверьте включение и обновите страницу. Мост работает только на `https://teenkode.github.io/ya-form-creator/`, в основной вкладке, не во фрейме. |
| Вход отменён / неверный Redirect URI | Проверьте регистрацию OAuth-приложения и фактический ID расширения. До исправления используйте ручной токен. |
| 401 | Токен истёк или неверен — войдите заново. |
| 403 | Проверьте права Forms, организацию и членство пользователя. |
| 429 | Дождитесь снятия ограничения. Перед повтором проверьте черновики. |
| Ошибка после создания формы | Откройте ссылку на частичный черновик. Уже принятые элементы остаются в Яндексе. Автоматического повтора и удаления нет. |
| Перезапуск фонового процесса / браузера | Проверьте кабинет Яндекса перед новой попыткой: операция могла выполниться частично. |

Лимиты веб-сборки: 150 исходных элементов, 200 после развёртки, 300 правил, безопасные целые числа JavaScript, JSON до 750 КБ. Время операции около четырёх минут: 230 секунд до начала следующего запроса, до 20 секунд на запрос. Для больших анкет используйте настольную версию. Неподтверждённая операция истекает через 30 минут. Не более 20 временных операций за сеанс; перезапуск браузера очищает их.

## OAuth-приложение владельца сервиса

Зарегистрируйте [приложение **«Для авторизации пользователей»**](https://oauth.yandex.ru/client/new/id/). В типе «Для доступа к API или отладки» адрес фиксирован как `verification_code` и для автоматического входа расширения не подходит.

- Платформа: **Веб-сервисы**.
- Redirect URI: `https://ojjljnbbienealjljlfklnfdpfemmlli.chromiumapp.org/oauth`.
- Разрешения: `forms:read`, `forms:write`, `directory:read_organization` (чтение организаций Яндекс 360).
- Публичный ClientID этой сборки: `a7f96f176b4241449864e48e3c3c6966`.
- Client secret не добавляйте в репозиторий, сайт или расширение.

Используется Authorization Code + PKCE S256 с проверкой `state` и адреса возврата. Фактический адрес расширение получает через `chrome.identity.getRedirectURL('oauth')`. Браузер перехватывает переход; размещать сайт на `chromiumapp.org` не требуется. При будущей публикации в магазине ID может измениться: сверяйте Redirect URI в настройках и регистрируйте его в Яндексе. Другой ClientID можно указать в расширении. Без верификации сервиса Яндекс может показывать предупреждение.

## Архитектура и приватность

```text
JSON / ручные вопросы → GitHub Pages: локальный редактор
                     → мост: анкета, открытие настроек, статус
                     → вкладка расширения: подтверждение
                     → фоновый процесс → api.forms.yandex.net
```

Сайт не получает токен или ID организации из расширения. Мост разрешает только `ping`, `options`, `prepare`, `status`. Вход, сохранение токена и создание доступны только собственным страницам расширения. Подтверждение проверяется в фоне. `TRUSTED_CONTEXTS` запрещает content script читать хранилище напрямую. API вызывается только на фиксированном хосте, с запретом редиректов; сырые ошибки не выводятся.

GitHub получает запросы за HTML/JS/CSS/ZIP, но JSON анкеты не отправляется в Actions, Issues или репозиторий. Нет аналитики, внешних шрифтов и удалённых скриптов. Расширение обращается к Яндекс OAuth для входа и API Форм для работы. Локальные файлы и данные профиля доступны владельцу профиля; хранилище расширения не является зашифрованным сейфом.

## Разработка и проверка

Python 3.12+, Node.js 22+:

```sh
python -m pip install -r requirements-dev.txt
npm ci
python scripts/build_browser.py
python -m unittest discover -v -p "test*.py"
npm test
npx playwright install chromium
npm run test:browser
```

Общий `browser/core.mjs` копируется сборщиком в сайт и расширение. Выходы: `web-dist/` для Pages, `browser-build/extension/` для установки, `web-dist/yaform-extension.zip` для скачивания. E2E использует изолированный Chromium и синтетический API, не создаёт живых форм. Тесты сравнивают Python/JS payload, проверяют PKCE/state, границу сайта/расширения, частичный результат, отсутствие автоматического повтора и явную публикацию. Они не подтверждают работу живого OAuth-приложения или доступ реального аккаунта.

Документация: [Chrome network requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests), [Chrome Identity](https://developer.chrome.com/docs/extensions/reference/api/identity), [Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/register-auth).
