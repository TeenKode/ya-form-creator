# Сайт и расширение YaFormCreator

**[Открыть веб-приложение](https://teenkode.github.io/ya-form-creator/)**. Оно размещается на GitHub Pages и работает без сервера приложения. Каждый пользователь подключает свой аккаунт и организацию; получает собственный токен. Аккаунт владельца репозитория не используется для создания чужих форм.

## Установка расширения

1. На сайте нажмите «Подключить расширение» → «Скачать расширение». [Прямая ссылка на ZIP](https://teenkode.github.io/ya-form-creator/yaform-extension.zip).
2. Распакуйте архив в постоянную папку. Не удаляйте её после установки.
3. Откройте управление расширениями: `chrome://extensions`, `edge://extensions` или страницу расширений Яндекс Браузера.
4. Включите **режим разработчика**, нажмите **«Загрузить распакованное»**, выберите папку с `manifest.json`.
5. Для этой распакованной сборки ожидаемый ID: `ojjljnbbienealjljlfklnfdpfemmlli`. Его закрепляет публичный ключ в manifest; это не секрет и не ключ доступа к Яндексу.
6. Обновите сайт. Должна появиться надпись «Расширение подключено».

Расширение пока не опубликовано в магазинах. Основная платформа — актуальный Chrome на компьютере. Edge и Яндекс Браузер поддерживают расширения Chromium, но OAuth следует проверять в конкретной версии браузера. Firefox и мобильные браузеры в эту сборку не входят. Для обновления замените файлы в папке, нажмите «Обновить» в управлении расширениями и перезагрузите сайт.

Сайт проверяет версию расширения и повторяет проверку перед отправкой анкеты. Если расширение старое или не сообщило корректную версию, нажмите **«Обновить расширение»**, скачайте ZIP, распакуйте поверх файлов установленного расширения и нажмите «Обновить» в управлении расширениями браузера. Затем обновите страницу сайта: после перезагрузки расширения связь со старой вкладкой может прерваться. При необходимости нажмите **«Проверить обновление»**. До успешной проверки создание недоступно; подготовка и сохранение анкеты продолжают работать. Минимальная версия расширения для этой версии сайта — 1.6.2; номер совместимого исправления может отличаться от версии сайта.

## Подключение Identity Hub за три шага

Сайт и расширение версии 1.6 поддерживают обычный Яндекс ID и организацию **Identity Hub**. Отдельный IAM-токен не нужен: [API Форм поддерживает OAuth и Identity Hub](https://yandex.ru/support/forms/ru/api-ref/access). Федеративные аккаунты, которым нужен IAM, в этом мастере не поддерживаются. Настольная версия сохраняет прежние способы входа.

1. **Вход.** Нажмите на сайте «Настроить подключение», затем «Войти через Яндекс». Подтвердите доступ к Формам. Свой ClientID создавать не нужно.
2. **Организация.** Нажмите «Открыть Identity Hub». Выберите организацию в левом верхнем углу Cloud Center. Если её нет, нажмите «Создать новую организацию», заполните данные и подтвердите условия самостоятельно. Откройте главную страницу, где виден ID под названием. Вернитесь в расширение и нажмите «Я выбрал организацию». Сверьте ID и нажмите «Проверить и подключить».
3. **Готово.** Расширение проверит доступ к Формам и сохранит организацию. Нажмите «Перейти к анкете».

Если автоматическое чтение не сработало, раскройте «Не получилось выбрать автоматически?», скопируйте ID под названием организации в Cloud Center и вставьте в поле. [Где Яндекс показывает ID](https://yandex.cloud/ru/docs/organization/operations/organization-get-id). Если доступ отклонён, проверьте выбранный аккаунт и наличие организации в [Формах для бизнеса](https://forms.yandex.ru/cloud/admin).

Расширение читает только видимый ID формата bpf… из своей открытой вкладки center.yandex.cloud или org.yandex.cloud по явному нажатию. Если найдено несколько ID, выбор не угадывается. Вкладка привязана к текущему входу на один час; новая вкладка или повторный вход начинает шаг заново. Страница кабинета — только источник кандидата: перед сохранением всегда выполняется GET /users/me в API Форм с OAuth и X-Cloud-Org-Id. Списки организаций через API 360 и Cloud больше не запрашиваются. Пароли, cookies и внутренние токены кабинета не читаются.

По умолчанию вход хранится до завершения сеанса браузера; «Запомнить вход на этом компьютере» сохраняет его в профиле. «Выйти» удаляет обе копии подключения. Старый вход через 360/IAM не считается действующим в новом мастере. При истечении входа авторизуйтесь заново. Для отзыва доступа приложения используйте безопасность Яндекс ID.

Создание организации выполняется пользователем в кабинете Яндекса, без внутреннего API. Мастер не подключает платёжные аккаунты или ресурсы. Стоимость подключённых сервисов проверяйте отдельно у Яндекса. Автоматическое чтение зависит от разметки кабинета; ручной ID остаётся запасным способом.

## Создание анкеты

Главный сценарий сайта 1.8.0 — создание с ИИ: опишите форму, скопируйте запрос с правилами в свой чат, затем верните ответ через «Вставить ответ ИИ» → «Показать форму». Подключение Яндекса понадобится только на последнем шаге. Сайт не обращается к ИИ автоматически. Описание сохраняется в localStorage; ответы предпросмотра остаются в памяти. Для отдельной инструкции без описания доступна кнопка «Только инструкция для ИИ». [Подробнее](AI_OFFLINE_RU.md).

1. Откройте UTF-8 JSON (до 750 000 байт) либо добавьте вопросы вручную. Для ИИ используйте [START_HERE_AI.md](../START_HERE_AI.md).
2. Проверьте вопросы и предпросмотр. В «Параметрах анкеты» доступны авторизация, повторные ответы и тексты отправки. В редакторе вопроса есть все типы, матрицы, многострочный текст, подсказки, диапазоны чисел и дат, длина текста, «Другое» и исключающие варианты. Сложные свойства API доступны в «JSON вопроса» или общем JSON.
3. Сохраните JSON на компьютер. Рабочая копия сохраняется также в localStorage сайта; очистка данных браузера удалит её. Ответы предпросмотра остаются только в памяти.
4. Нажмите **«Создать в Яндексе»**. Откроется вкладка расширения с названием, полным JSON, числом вопросов и организацией.
5. Проверьте данные, отметьте подтверждение и нажмите **«Создать черновик»**. Публикация выключена по умолчанию независимо от `publish_by_default` в файле. Для неё нужно отдельно поставить флажок в расширении.
6. Откройте редактирование созданной формы в Яндексе и проверьте результат.

Каждый запуск создаёт **новую** форму. Обновление существующих анкет и сбор ответов не поддерживаются. Не закрывайте браузер во время отправки.

### Редактор и логика (сайт 1.7.0)

- Кнопка дублирования создаёт новый код вопроса и копирует его входящие условия показа. Исходный вопрос и зависящие от него вопросы сохраняют свои связи.
- При переименовании кода вопроса обновляются условия, в том числе ссылки на дополнительное поле «Другое». При удалении показывается количество связанных условий; они удаляются вместе с вопросом после подтверждения.
- «Условия показа» позволяет добавлять, изменять и удалять правила: предыдущий вопрос, ответы, совпадение/несовпадение и И/ИЛИ. Несколько правил для одного вопроса действуют вместе (И). Изменения вступают в силу по кнопке «Сохранить условия»; закрытие окна отменяет их.
- «Проверка логики» (F6) локально ищет вероятные противоречия по тем же эвристикам, что настольная версия. Можно применить выбранные предложения или все, после подтверждения. Существующие сложные условия требуют ручной проверки. Проверка структуры и отправка в Яндекс предупреждают о найденных проблемах.
- Ctrl+N — новая анкета, Ctrl+O — открыть файл, Ctrl+S / Ctrl+Shift+S — скачать JSON, F5 — перейти к предпросмотру. В браузере скачивание выполняется через его обычный механизм сохранения; прямой перезаписи открытого файла нет.

Общий формат JSON, API-payload и автоматическое преобразование исключающих ответов сохранены. Подключение остаётся через Identity Hub; 360 и IAM в веб-версию не добавлены. Действуют прежние лимиты веб-сборки. `publish_by_default` сохраняется для совместимости с настольной версией; в расширении публикацию по-прежнему нужно выбрать отдельно.

### Специальные поля

Сохраняется контракт настольной версии 1.2+: `text` с `format: full_name / phone / email / url / inn / decimal`. ФИО не требует обязательного отчества; телефон РФ использует нативный валидатор Яндекса. Номер документа с ведущими нулями — обычный текст, счётчик — `integer`, дробное число — `text + decimal`. Уникальный `slug` означает код вопроса, а не запрет повторных ответов. [Справочник полей](FIELD_GUIDE_RU.md).

## Ошибки и ограничения

| Ситуация | Что делать |
| --- | --- |
| Сайт не видит расширение | Проверьте включение и обновите страницу. Мост работает только на `https://teenkode.github.io/ya-form-creator/`, в основной вкладке, не во фрейме. |
| Вход отменён / неверный Redirect URI | Проверьте регистрацию OAuth-приложения и фактический ID расширения. Повторите вход после исправления. |
| 401 | Токен истёк или неверен — войдите заново. |
| 403 | Проверьте права Forms, организацию и членство пользователя. |
| 429 | Дождитесь снятия ограничения. Перед повтором проверьте черновики. |
| Ошибка после создания формы | Откройте ссылку на частичный черновик. Уже принятые элементы остаются в Яндексе. Автоматического повтора и удаления нет. |
| Перезапуск фонового процесса / браузера | Проверьте кабинет Яндекса перед новой попыткой: операция могла выполниться частично. |

Лимиты веб-сборки: 150 исходных элементов, 200 после развёртки, 300 правил, безопасные целые числа JavaScript, JSON до 750 КБ. Время операции около четырёх минут: 230 секунд до начала следующего запроса, до 20 секунд на запрос. Для больших анкет используйте настольную версию. Неподтверждённая операция истекает через 30 минут. Не более 20 временных операций за сеанс; перезапуск браузера очищает их.

## OAuth-приложение владельца сервиса

Зарегистрируйте [приложение **«Для авторизации пользователей»**](https://oauth.yandex.ru/client/new/id/). В типе «Для доступа к API или отладки» адрес фиксирован как `verification_code` и для автоматического входа расширения не подходит.

- Платформа: **Веб-сервисы**.
- Redirect URI: `https://ojjljnbbienealjljlfklnfdpfemmlli.chromiumapp.org/oauth`.
- Разрешения: `forms:read`, `forms:write`.
- Публичный ClientID этой сборки: `a7f96f176b4241449864e48e3c3c6966`.
- Client secret не добавляйте в репозиторий, сайт или расширение.

Используется Authorization Code + PKCE S256 с проверкой `state` и адреса возврата. Фактический адрес расширение получает через `chrome.identity.getRedirectURL('oauth')`. Браузер перехватывает переход; размещать сайт на `chromiumapp.org` не требуется. При будущей публикации в магазине ID может измениться: сверяйте Redirect URI в настройках и регистрируйте его в Яндексе. Другой ClientID можно указать в расширении. Без верификации сервиса Яндекс может показывать предупреждение.

## Архитектура и приватность

```text
JSON / ручные вопросы → GitHub Pages: локальный редактор
                     → мост: анкета, открытие настроек, статус
                     → вкладка расширения: подтверждение
                     → фоновый процесс → api.forms.yandex.net
```

Сайт не получает токен или ID организации из расширения. Мост разрешает только `ping`, `options`, `prepare`, `status`. Вход, сохранение токена и создание доступны только собственным страницам расширения. Подтверждение привязано к показанному аккаунту и организации; при смене подключения необходимо подтвердить создание заново. Выход отменяет незавершённый вход. Подтверждение проверяется в фоне. `TRUSTED_CONTEXTS` запрещает content script читать хранилище напрямую. API вызывается только на фиксированном хосте, с запретом редиректов; сырые ошибки не выводятся.

GitHub получает запросы за HTML/JS/CSS/ZIP, но JSON анкеты не отправляется в Actions, Issues или репозиторий. Нет аналитики, внешних шрифтов и удалённых скриптов. Расширение обращается к Яндекс OAuth для входа и API Форм для работы. Локальные файлы и данные профиля доступны владельцу профиля; хранилище расширения не является зашифрованным сейфом.

## Разработка и проверка

Python 3.12+, Node.js 22+:

```sh
python -m pip install -r requirements-dev.txt
npm ci
python scripts/build_browser.py
node scripts/build_opera.mjs
python -m unittest discover -v -p "test*.py"
npm test
npx playwright install chromium
npm run test:browser
```

Общий `browser/core.mjs` копируется сборщиком в сайт и расширение. Выходы: `web-dist/` для Pages, `browser-build/extension/` для установки, `web-dist/yaform-extension.zip` для скачивания. E2E использует изолированный Chromium и синтетический API, не создаёт живых форм. Тесты сравнивают Python/JS payload, проверяют PKCE/state, границу сайта/расширения, частичный результат, отсутствие автоматического повтора и явную публикацию. Они не подтверждают работу живого OAuth-приложения или доступ реального аккаунта.

Документация: [Chrome network requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests), [Chrome Identity](https://developer.chrome.com/docs/extensions/reference/api/identity), [Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/register-auth).
